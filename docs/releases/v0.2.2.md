# v0.2.2 release notes

Release type: maintenance patch. Validation passed for the declared Web scope. The npm tarball is prepared for the maintainer to publish with 2FA; npm publication status is recorded separately from GitHub.

Maintenance patch over v0.2.1. Repairs TEST-001–004 and BUG-001–007, fixes UX-001, and adds defensive hardening for RISK-001.

- Strengthens isolated test-directory ownership and production-path exclusion.
- Ensures one custom Worker dispatch and validates response identity, schema versions, physical exit, and bounded uncertain termination.
- Recovers first-import snapshots and makes failed catalog deletion explicitly retryable.
- Cancels/unlocks failed ECDICT responses while preserving primary errors and existing caches.
- Rejects stale text-selection gestures and invalid snapshot activation.
- Keeps confirmation focus stable during management refresh.
- Corrects bundle and smoke verdicts so failures and missing evidence cannot become PASS.

The BUG-003 pending-cancel test now requires cancellation entry and executes every timer/outcome assertion.

Known v0.2.1 limitations remain: the narrow F03 pending settings-sync crash window, optional selection OS/DPI differences, custom escape ambiguity, and no formal Desktop compatibility claim. Full ECDICT is neither downloaded nor shipped. Native Worker terminate refusal/indefinite delay remains unreproduced; controlled injection validates the hardening only.

See the pre-release verification report for exact executed checks, artifact hashes, and remaining gates. Historical v0.2.1 evidence does not certify this candidate.

The owner selected the current installed carrier as the new release baseline. Its actual CLI version is DSH `0.2.1-rc.3` (Electron Node `v24.21.0`), verified using a new isolated Web profile. Installation, startup, real Fixture lookup, settings, measured UI formatting/scrolling, and uninstall absence were verified. Both instrumented Host lifetimes and browser page requests had zero non-loopback attempts. Network sensors block external attempts, and their local positive control was run on the actual carrier. Registry child processes were limited to local read-only App Paths/Uninstall queries; no unobserved worker or other child process was accepted. This is an instrumented plugin smoke window, not a packet-level guarantee or a general native-network audit. Desktop profile, rollback, full corpus, earlier baselines and other runtimes remain unverified for this candidate.

## Observed runtime limitation

Keeping a browser open across an intentional Host stop/restart can produce DSH `SlotAssemblyError: scope 'session-maybe' rendered without an installed adapter`. The same error was reproduced twice in a fresh Web profile with no external plugins installed. Normal install/uninstall acceptance closes the browser before stopping the Host and opens a new context after restart; the final candidate passed all 22 checks with no page errors. Live browser recovery across a Host restart is not part of this release's compatibility claim. Historical failing reports and the no-plugin control are preserved.

## Windows SQLite path boundary

The publication verification initially produced 34 failures in three import/Worker suites because the longer audit TMP root made a real candidate path 262 characters. Its parent and reserved file both existed. Minimal synthetic probes confirmed that Node 24.13.0 and the installed carrier Node 24.21.0 opened 259-character SQLite paths and rejected 260/270/300-character paths. The unchanged suite was rerun in a shorter private root; original failures and probes remain evidence. Keep complete SQLite/candidate paths below 260 characters in these measured Windows runtimes. No production code, assertions, dependencies, Windows configuration or user data were changed to make that run pass.
