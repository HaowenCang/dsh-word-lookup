# dsh-word-lookup v0.2.1 Release Notes

- **Package**: `dsh-word-lookup@0.2.1`
- **Release Type**: Maintenance Patch Release
- **Date**: October 2026
- **License**: MIT
- **Target Baseline**: DSH `0.2.0-rc.2` (Web Profile)

This is a maintenance patch release focused on UI text formatting, multiline translation/definition layout rendering, lexical part-of-speech badge boundary refinement, and settings UI label cleanup. It preserves the core zero-token local SQLite dictionary architecture without architectural regressions.

---

## Changes in v0.2.1

### Fixed
- **Multiline Chinese Translation Formatting**: Properly parses and formats both real newlines (`\n`, `\r\n`) and literal escape sequences (`\n`, `\r\n`) in Chinese glosses, rendering each definition line as a distinct block rather than an unformatted single paragraph.
- **Multiline English Definition Formatting**: Renders multi-paragraph English definitions cleanly with dedicated block spacing.
- **Structured Multi-Sense Layout**: Ensures distinct parts of speech and numbered senses render structured, readable line sequences.
- **POS Badge Duplication & Conflict Remediation**: Suppresses the top-level part-of-speech badge when translation lines already begin with explicit POS abbreviations (e.g., `n.`, `v.`, `vt.`), eliminating contradictory and duplicated prefix badges such as `v.n.`.
- **Settings UI Outdated Text**: Replaced the obsolete "Phase 7A.8 开放" label in the Custom SQLite dictionary settings section with the accurate "已支持" status badge.

### Improved
- **Lexical POS Boundary Detection**: Tightened POS detection regular expressions to accurately recognize standard dictionary abbreviations and bracketed forms while preventing false positive matches on legitimate words or digits.
- **Narrow Viewport Responsiveness**: Refined dictionary card CSS layout to ensure clean wrap and avoid horizontal truncation or layout overflow on compact viewports (~320px width).
- **Long-Entry Vertical Scrolling**: Verified smooth vertical scrolling on long multiline entries with bounded maximum card height.
- **UI Test Coverage**: Added comprehensive rendering and interaction regression tests covering single-line, multiline, mixed-POS, and edge-case gloss structures.

### Unchanged
- **Local SQLite Architecture**: Word lookups remain powered strictly by local SQLite (`node:sqlite`) with prepared statements and indexed lookups.
- **On-Demand ECDICT Download**: The full 800MB ECDICT database is not bundled in the distribution package and is installed only upon explicit user request via the settings UI.
- **Custom SQLite Snapshot Management**: Point-in-time immutable snapshot isolation via `VACUUM INTO` ensures user source databases are never modified, moved, or deleted.
- **Gesture Switches Default Off**: Both automatic double-click (`autoDoubleClick`) and drag-selection (`autoSelection`) switches strictly default to `false`.
- **Zero AI / Zero Token Consumption**: All queries run locally on-device with zero calls to remote translation APIs or LLM model endpoints.

## Known Limitations

1. **Scenario F03 Crash Recovery Manual Synchronization**: If a process crash occurs during transition from custom dictionary mode to built-in fixture mode immediately after disk unlinking of `active.json`, the data plane safely falls back to the built-in fixture dictionary, but host configuration may display `settingsSyncState: 'pending'`. The user must click the dictionary mode once in Settings to re-synchronize host settings.
2. **Automatic Drag-Selection Portability**: `autoSelection` is validated in standard Windows/Chromium environments. Due to platform differences in pointer events, multi-click timing, and display server scaling, it remains opt-in (default OFF). The keyboard shortcut (`Primary+Shift+L`) is the recommended primary method.
3. **ECDICT Corpus Redistribution**: Full ECDICT database is not bundled in npm or GitHub packages and requires a one-click on-demand download.
4. **Custom SQLite Backslash Ambiguity**: In custom SQLite dictionaries, literal backslash-n sequences (`\n`) are treated as newline delimiters per ECDICT formatting conventions; literal backslashes preceding `n` or `r` should be double-escaped (`\\n`) if intended as raw characters.
5. **Unverified DSH Environments**: Environments outside the measured baseline (such as Desktop wrappers or unverified releases) are not declared compatible.
