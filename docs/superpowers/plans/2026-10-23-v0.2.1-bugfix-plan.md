### 3.1 接口与实现决策

1. 保留 `normalisePath(path): string` 的公共入口，改为从目标逐层向上寻找最近存在的祖先，对该祖先执行 realpath，再拼接缺失后缀。Windows 比较继续大小写折叠。
2. 使用能区分 ENOENT 与权限/解析错误的操作；只有明确不存在才向上查找。EACCES、EPERM、ENOTDIR、损坏链接和无法解析的路径拒绝，不回退为“看起来在目录内”的字符串。
3. 对实际测试根、home、profileDir 及递归删除目标检查 `candidate ⊆ production` 和 `production ⊆ candidate`；任一成立即拒绝。比较必须带路径分隔边界。
4. `--test-root` 保留为准确的目标路径：新运行要求该目录不存在，并以排他创建方式建立。既有目录直接拒绝，不通过在旧目录中写 marker 来取得删除权。默认路径继续使用独有随机目录。
5. 新辅助模块提供以下接口，保持测试环境中的生产事实可注入：

   ```ts
   createOwnedTestRoot(options: {
     requestedRoot?: string
     env?: Record<string, string | undefined>
   }): Promise<OwnedTestRoot>

   cleanupOwnedTestRoot(owner: OwnedTestRoot): Promise<void>
   ```

   `OwnedTestRoot` 是不由 CLI JSON 构造的运行时所有权对象，保存原始路径、创建后的 canonical path、随机 nonce、根目录身份及 marker 身份。调用者不传任意删除路径。
6. 创建前验证拟用路径，创建后再次验证实际路径；marker 使用排他创建。清理时重读 marker、核对 nonce 和目录身份，重新执行隔离、链接及生产重叠检查；任一不一致时保留目录并报告清理拒绝。
7. Release runner 只清理所持 `OwnedTestRoot`，不得直接 `rmSync(options.testRoot)`。先将证据保存到清理范围外，确认自有子进程退出及端口释放；`keep-evidence` 仍保留目录。
8. 检查共用 guard 的调用者及递归删除入口，至少包括现有 profile cleanup。不得因测试根安全而省略对实际删除 home 的检查。

这是受控本地测试目录的保护，不声称用户态“检查后删除”能消除恶意外部进程并发替换目录的所有竞态。目录所有权或路径稳定性无法证明时，拒绝自动递归清理。

## 5. T3：收敛下载响应流生命周期（BUG-003）

**修改与测试文件：** [ecdict-downloader.ts:594](E:/Projects/DSHarness/dsh-word-lookup/src/host/ecdict-downloader.ts:594)、[ecdict-downloader.spec.ts](E:/Projects/DSHarness/dsh-word-lookup/tests/ecdict-downloader.spec.ts)。

**审计证据：** 内存流先发送非法 UTF-8、随后保持 open，函数拒绝后 `cancelled=0`、`body.locked=true`，虽然 part 文件已清理。

### 5.1 实现合同

1. Reader 在其获取位置建立明确 try/finally 所有权，记录是否正常 EOF。
2. 未正常 EOF 时，包括文件 write、UTF-8 decode、read rejection、用户取消和字节上限拒绝，执行取消；始终尝试 releaseLock。
3. 将已有分支上的 cancel 合并到统一清理，避免重复取消及遗漏；已有非 200、重定向和 Content-Length 拒绝仍清理相应 response。
4. 生产 fetch 使用本次下载的 AbortController，将调用方 AbortSignal 转发到它；失败时中止本次传输。结束时移除转发监听，不中止调用方拥有的 controller。
5. Reader 清理错误不得覆盖原始 write/decode/read 错误。内部使用 `STREAM_CLEANUP_TIMEOUT_MS = 1000` 限制取消等待，测试用 fake timer 验证，不向用户设置新增参数；这是清理等待上限，不是整个下载期限。若取消无法及时确认，记录清理未确认并依靠本次 fetch abort 终止传输，不宣称清理已证实成功。
6. 保留 exact bytes、SHA-256、fatal UTF-8、来源固定和原子发布合同；错误时不发布最终缓存，不影响既有有效缓存。关闭自己的文件后才删除自己的 part。

无需引入新的网络库或自动重试。此次修复解决清理，不声称已测出真实 socket 泄漏数量。

### 6.2 BUG-007：文件删除与 catalog 删除分别报告，支持跨重启重试

| 删除结果 | catalog 结果 | 返回/状态 | 重启后的处理 |
| --- | --- | --- | --- |

| 文件删除失败 | 未执行写入 | 失败 / CLEANUP_PENDING | 原对象保持，用户可重试 |
| 文件删除成功 | 写入失败 | 失败 / CLEANUP_PENDING | 已知缺失文件记录允许登记清理 |
| 已知文件仍缺失 | 登记清理成功 | true / DELETED | 无记录 |
| 缺失文件路径出现替代对象 | 不写入 | 冲突、保留对象 | 重新核验，禁止自动删除 |
